# Pindo 产品设计草案 v0.5

本文保留 v0.5 网页原型的设计记录。用户已授权开发，现已新增 SwiftUI／AppKit 原生源码；当前实现、构建方式和验证范围以仓库 [README](../README.md) 为准。网页原型的桌面背景与介绍仅为展示容器，不代表原生应用截图。

## 已确认的产品方向

| 项目 | 当前决定 |
| --- | --- |
| 入口 | 菜单栏为主，点击图标展开紧凑面板 |
| 核心使用场景 | 先记想法为待办，再挑选交给 Codex；等待其恢复、运行时继续挑其他事项并行推进，在两边往返，人工确认后勾选完成 |
| 信息结构 | 只有待办清单。便签是每条待办的附属备注，每条最多一份 |
| 便签入口 | 点击待办文字或行内主体打开备注；修改待办改为右侧独立铅笔图标 |
| 备注编辑 | 纯文本、多行、自动保存。备注没有独立标题或列表 |
| 日期 | 左右箭头逐日切换；日期旁下箭头展开日期列表，支持快速跳转 |
| 分组 | 工作、生活等简单分组；待办行最左侧用 3px 色条区分，颜色可在设置里修改 |
| 背景 | 原生 macOS 磨砂玻璃材质，适配系统深浅色 |
| 数据 | 第一版自己用，本机保存，无账号和同步 |
| 跨日 | “之前未完成”折叠区，用户手动移到今天，不自动迁移 |
| 提醒／重复 | 第一版不加入 |
| 快速记录 | 可自定义全局快捷键，呼出输入框创建待办 |
| 自动备份与恢复 | 每 30 秒检查，有变化才合并生成一份快照；最多 100 份、总计 30 MB，仅在完整设置页中恢复 |

## 面板布局

默认建议约 370 × 582 pt，后续根据真实 Mac 字体、屏幕与使用体验调整。

```text
菜单栏： ☑ 3
         ↓
┌────────────────────────────┐
│ Pindo                ＋  ⚙ │
│                            │
│ ‹         今天 ⌄         › │
│       11月6日，星期五      │
│ 全部分组 ▾                 │
│ ────────────────────────── │
│ ▸ 之前未完成 · 1 件        │
│                            │
│ ▏ ○ 把首页的设计简化   ✎   │
│ ▏   工作                   │
│                            │
│ ▏ ○ 下班买咖啡豆       ✎   │
│ ▏   生活                   │
│                            │
│ ▸ 已完成 · 1 件            │
│                            │
│ ＋ 添加一件要做的事…    ↵  │
│ 2 件待办            仅本机  │
└────────────────────────────┘
```

- 顶部仅保留名称、新建待办和齿轮设置入口，不显示撤销按钮，也不展开多项下拉菜单，不设置“待办／便签”页签。
- 日期确定查看哪一天，分组只负责筛选，例如“明天 + 生活”。不增加侧边栏。
- 点击待办文字、分组说明或行内空白打开备注；右侧铅笔只用于修改标题、日期与分组。勾选按钮只负责完成／恢复，不会打开备注。
- 已有备注在待办文字旁显示小提示图标，右侧修改图标始终可见。
- 分组名称仍显示，避免只靠颜色传达信息。色条表示分组，与优先级无关。
- 菜单栏数字建议仅统计今天未完成的事项，不受面板当前日期和分组筛选影响，零时只显示图标。
- 默认不显示 Dock 图标；原生版退出入口放在设置页底部，不依赖多项下拉菜单。
- 面板外点击收起；Esc 优先关闭日期快选或返回上一级，再收起面板。已有备注与未提交草稿保留。

## 每条待办的附属便签

### 编辑流程

1. 点击待办事项的文字或行内主体，在同一面板中进入该事项的备注页。右侧铅笔另用于修改待办信息，两种操作不混用。
2. 页首显示“这件事的备注”、所属待办标题、分组与计划日，明确内容归属。
3. 下方直接编辑纯文本，不需要额外填写标题，不要求点保存。
4. Return 换行，支持复制、剪切、粘贴与原生文本撤销。保存状态显示在页首。
5. “返回待办”扩大为至少 42pt 高的整行可点击区域。点击备注正文编辑框以外的程序区域，例如标题、备注所属事项、两侧留白、底栏，也返回原日期和分组清单；该次点击仅返回，不顺带触发其他页面动作。点击程序外部仍收起面板。
6. 正文编辑框及其内部字数／清空工具区构成明确的编辑区域，区域内点击、选字、滚动、清空不触发返回。返回不会清空备注，自动保存状态与修改历史继续保留。

```text
┌────────────────────────────┐
│ Pindo                ＋  ⚙ │
│ ‹ 返回待办          已保存 │
│                            │
│ 这件事的备注               │
│ 把首页的设计再简化一点     │
│ ▏工作 · 11月6日，星期五    │
│ ────────────────────────── │
│ 先保留最常用的入口。       │
│                            │
│ 日期支持左右切换，分组     │
│ 用细色条区分……             │
│                            │
│ 48 字             清空备注 │
│ 点击编辑区外返回    仅本机  │
└────────────────────────────┘
```

### 数据与边界

- 一条待办拥有一份可为空的备注。不会产生独立便签，也没有便签创建、分组、排序等额外体系。
- 修改待办标题、日期、分组，或将其完成／恢复时，备注始终跟随同一待办。
- 已完成待办仍可查看和编辑备注。
- 删除待办时一并删除备注；从设置中恢复旧快照时，应恢复整个事项及其备注。不提供逐次操作撤销，30 秒内的中间状态可能未单独备份。
- 清空备注不删除待办，需要找回时在设置中恢复相关快照。删除分组不删除待办及其备注，只转为未分组。
- 当前内容与备份分开处理：文字输入在停止约 600ms 后自动保存，返回、失焦、收起和退出时补存；不逐字写入修改历史。失败时保留内存内容并显示未保存。备份另由 30 秒定时检查生成。

## 日期导航

- 左箭头：相对当前查看日期减一天；右箭头：加一天。可以连续翻历史或未来，不固定只切“昨天／明天”。
- 中间显示“今天／昨天／明天”或具体月日，下面显示完整日期与星期。
- 日期旁的下箭头展开快速选择：附近七天的日期列表，以及“今天、明天、一周后”快捷入口。
- 列表底部提供任意日期选择，便于跳到较远日期。日期选中后收起列表，更新待办清单。
- 离开今天后显示“回到今天”。切换日期不改变当前分组筛选。
- 日期栏支持水平滑动：左滑到下一天，右滑到前一天。手势只在日期栏响应，待办列表继续用于垂直滚动。
- 可用 `Command + [` / `Command + ]` 逐日切换，保留点击操作和清晰焦点。
- 计划日采用本地日历语义，原生版需覆盖月末、年末、闰年、夏令时及系统时区变化。

### 之前未完成

今天显示“之前未完成”折叠区，保留事项原计划日。用户可以直接完成、编辑单条计划日，或将当前筛选范围中的历史未完成批量移到今天，需要恢复时在设置中选择此前快照。

不自动改变历史日期，不移动已完成或未来事项。移入今天前，这些事项不计入今天的菜单栏数字。应用跨日、唤醒或重启只刷新日期与视图，不自动迁移数据。

## 分组与颜色设置

- 每条待办最左侧显示 **3px** 竖向色条，顶底各留约 10pt 空间，小圆角；不把整行涂成彩色卡片。
- 默认示例：工作为低饱和蓝色，生活为低饱和暖棕色，未分组为中性灰。示例颜色可自行修改。
- “齿轮 → 分组”在完整设置页中管理名称与颜色，可新建、改名、改色和删除。
- 颜色修改后即时应用到所有日期、历史未完成、已完成及备注页的所属分组标识；重启后保留。
- 分组使用稳定标识关联事项，改名称或颜色不改变关联。删除分组后保留事项与备注，转为未分组。需要撤回时从“备份与恢复”选择旧快照。
- 可自选颜色，但分组文字和 VoiceOver 标签始终保留；完成状态由勾选表达，不借用分组色表示状态。

## 磨砂玻璃背景

目标是 macOS 原生材质：背景内容经过模糊与适度透色，文字、按钮和色条保持清晰。不把整个窗口调低透明度，也不使用纸张底色代替玻璃。

原生实现建议：

- 用 AppKit `NSVisualEffectView` 承载 SwiftUI 内容，面板材质优先 `.popover`，`blendingMode = .behindWindow`，配合透明窗口及透明宿主背景。
- 窗口 `isOpaque = false`、`backgroundColor = .clear`，整体 `alphaValue` 保持 1；避免降低文字对比度。
- 材质随系统深浅色自适应，尊重“减少透明度”“提高对比度”等辅助设置。不要在材质上再覆盖高不透明度的平面底色。
- 原型用半透明背景、`backdrop-filter: blur(32px) saturate(155%)`、微弱纹理和边缘高光来模拟。可以点击外层“切换壁纸”检查透色效果；外层按钮不属于实际产品。
- 浏览器效果不能证明真实 macOS 跨窗口材质已实现，仍需 Mac 真机验收。

## 快捷记录

- 已确认需要自定义全局快捷键；暂建议 `Control + Option + Space`，实际初始值可调整。提供录制、启停、冲突检测、失败回退。
- 从其他应用呼出紧凑输入框，默认今天、未分组，独立于主面板正在查看的日期或筛选。
- 只创建待办，**没有独立便签模式**。可展开“添加备注”，与新待办一起保存。
- 标题输入中 Return 创建并收起；备注中 Return 换行，`Command + Return` 提交。没有待办标题时不会只创建一份备注。
- Esc、点击外部或再次按快捷键收起；待办标题与附属备注作为同一个草稿保留，重新呼出可继续。
- 成功后清空草稿并恢复原前台应用；失败时保留内容。正确处理中文输入法确认回车。
- 网页只演示页内热键、输入与草稿。系统全局注册、跨应用焦点恢复、真实系统快捷键冲突检测需原生验证。

## 完整设置界面

右上角齿轮直接打开完整的设置窗口，采用左侧分类、右侧内容布局，不再弹出包含多项操作的下拉菜单。原生版建议独立 `Settings` 窗口，网页原型使用完整设置对话框模拟。

| 分类 | 可设置／操作的内容 |
| --- | --- |
| 通用 | 跟随系统／浅色／深色、登录时启动、菜单栏今日数量、默认展开已完成 |
| 分组 | 分组名称、3px 色条颜色、新建与删除，修改自动保存 |
| 快捷记录 | 启停热键、录制组合键、恢复默认、保存修改 |
| 备份与恢复 | 自动快照状态、保留数量与空间、快照列表、确认后恢复旧版本 |

偏好修改在本机保存。登录启动与全局热键在网页中只保存和演示设置，系统注册需原生实现。主界面不展示撤销、重做或备份按钮，删除等操作后的提示也不附带撤销按钮。普通文本框保留系统自身的文本撤销，不把 Command + Z 拦截为应用级历史恢复。

## 30 秒自动快照与按需恢复

### 当前保存与备份分开

- 文字输入停止约 **600ms** 后保存当前资料，返回或关闭面板时立即补存；防止逐字频繁写入，也不必等待 30 秒才能保存正文。
- **每 30 秒检查一次**待办、附属备注、日期／分组、分组颜色、快捷键与通用偏好；相对上一份快照没有变化就跳过。
- 一个检查周期内的连续编辑合并为一份快照，不按字符、输入事件或每次编辑保存生成历史。浏览日期、展开清单、未提交输入草稿不生成备份版本。
- 即使退出时尚未达到下一次 30 秒检查，当前内容仍会补存。重新启动后如当前资料与最后快照不同，在下一次检查时合并备份；不靠逐操作快照补齐中间状态。
- 快照是供误改、误删或找回旧资料时按需使用，不是日常需要反复点击的撤销功能。

### 保留与性能

- 最多保留 **100 份快照（包含保留范围的基线）**，备份总量最多 **30 MB（30,000,000 字节）**。任一上限达到时合并并清理最旧快照，优先保留最近版本。
- 用户看到的是按时间排列的快照；存储可采用一份基线加检查点间的增量，备注记录检查点之间的文本差异。只在 30 秒检查时比较和生成备份，不在每个输入事件中计算差异。
- 清理时把最早增量合并进基线，剩余版本仍可恢复。30 MB 包含备份基线、增量和元数据，不包括当前主数据文件。
- 已有资料不因备份限额或失败而删除。当前保存与快照状态分别提示，不能把备份失败误称为成功。若浏览器提前触及配额，保留已有快照并说明失败。

### 设置内恢复

1. 需要找回旧资料时，打开“齿轮 → 备份与恢复”。
2. 查看每份快照的时间、概要、保留数量及空间占用，选择“恢复…”。
3. 在设置页内确认具体时间，确认前不修改资料，可取消。
4. 恢复前先补存当前内容，并在有差异时生成保护快照；然后恢复待办、备注、分组、快捷键及通用偏好。
5. 恢复结果另记为恢复快照，保留之后已有的版本，便于再次找回，不采用“撤销后编辑就清除重做分支”的操作栈逻辑。

恢复前后的保护快照是用户明确进行恢复时的例外，不会让平常编辑重新变成逐操作备份。恢复和保护快照作为一次原子提交，失败时保留当前资料与原备份。正常主数据保存无需等待定时快照，但每次快照包更新及合并整理需事务或原子替换。

网页原型使用浏览器存储验证定时、合并、保留和恢复交互；通过浏览器时钟推进验证生产代码中的真实 30 秒定时器。它不等于原生磁盘备份验证。

## 第一版范围与实现

用户要求先讨论流程、不改变结构。讨论内容记录在 [多项目事项流程讨论稿](multi-project-workflow.md)，聚焦“今天推进什么、在等什么、需要确认什么、下一步做什么”。状态标记、聚焦和摘要仍是建议，不视为 v0.5 已实现功能；不引入具体开发项目管理或 AI 工具联动。

用户进一步说明了与 Codex 桌面应用反复往返、趁恢复／运行等待并行挑选事项的过程。最新方案见 [Pindo 与 Codex 的往返流程提案](codex-handoff-flow.md)：优先讨论“待开始／进行中／已完成”、唤出已有清单的快捷键，以及“复制并切到 Codex”。已核对官方桌面启动实现；定位到已有具体任务仍待验证。尚未改动原型，不把激活应用描述为任务已发送或已恢复。

第一版包括：菜单栏清单、按日浏览与日期快选、分组及颜色、待办增删改／完成、每条事项的纯文本备注、手动处理历史未完成、可自定义全局快速记录、本机存储、30 秒自动快照与设置内按需恢复。

不加入独立便签列表、到点提醒、重复待办、云同步、桌面悬浮便签、AI、富文本或附件。

建议 SwiftUI + AppKit，优先 macOS 14+，待确认用户 Mac 版本。菜单栏使用 `NSStatusItem` + `NSPopover` 或评估 `MenuBarExtra(.window)`；全局记录框用 `NSPanel`。存储层可选 SwiftData 本地容器，与视图隔离。

最小数据：

| 实体 | 主要内容 |
| --- | --- |
| Task | 唯一标识、标题、计划日、分组标识、备注文本、备注修改时间、完成时间、排序、删除时间 |
| Group | 唯一标识、名称、颜色、排序 |
| Preferences | 全局快捷键、登录启动、外观、菜单栏数字与已完成显示偏好 |

无需独立 Note 实体；备注不取第一行作为单独标题。任务删除与恢复、数据导入导出均必须携带备注，分组导入导出携带颜色。本机数据放 Application Support，具有结构版本和备份机制。
