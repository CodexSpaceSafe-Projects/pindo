# Pindo 与 Codex 的往返流程提案

状态：用户已确认开发，相关流程已写入原生源码：待开始／进行中／已完成、唤出清单、复制标题及附属备注、保存进行中状态并激活 **Codex 桌面应用**。v0.5 网页原型保留为历史设计记录。当前构建和验证状态见 [README](../README.md)。已核对官方启动实现；直接打开某条已有会话尚未实现，也不自动发送消息或判断任务完成。

## 已确认的实际过程

1. 想到一件事，先记成待办。
2. 准备处理时，从清单中挑一条，在 Codex 中开发或继续工作。
3. Codex 恢复、运行期间，回到 Pindo 再挑另一条，交给另一个 Codex 任务并行推进。
4. 在 Pindo 与 Codex 之间来回切换，可有多件事同时进行。
5. 某件事完成并经过自己确认后，在 Pindo 勾选完成。

Pindo 负责挑选、记住哪些已开始、连接回原事项与完成收尾；具体工作、项目管理和执行仍在 Codex。

## 第一轮建议：三个状态、两块常用区域

| 状态 | 说明 |
| --- | --- |
| 待开始 | 已记录，还没挑出去做 |
| 进行中 | 用户已决定开始，正在 Codex 中推进或回来检查 |
| 已完成 | 用户检查后，使用现有勾选操作确认完成 |

“进行中”允许同时有多条，不要求一条完成后才能开始另一条。第一轮不强制增加“等结果、待验收”等更多状态，也不把复制任务当作 Codex 已实际收到或执行成功的证据。

常态清单可以优先区分：

- **进行中**：方便回来找到已交出去的事项与附属备注。
- **待开始**：等待时继续从这里挑一条。
- 已完成继续折叠，作为低频回看内容。

这两块仍是同一份待办清单，不引入项目层级或复杂看板。事项归属沿用现有分组与颜色。

## 最值得缩短的四个动作

### 1. 在 Codex 中随时唤出已有清单

现有全局快捷键只打开新建输入框，适合记录想法，但无法直接挑选已有事项。建议保留快捷记录，另外提供可自定义的“唤出待办清单”快捷键：等待 Codex 时直接打开清单，用鼠标或键盘选事项，不用先找到 Pindo 的窗口。

清单仍保留原来的事项点击与备注交互，不把普通单击或回车暗中改成发起开发。复制并开始使用明确动作。

### 2. 从待办带走内容

桌面版建议提供明确的“复制并切到 Codex”动作：

- 把任务标题与附属备注整理成适合粘贴到 Codex 的文本。
- 复制成功后，按用户的主动操作将事项标为进行中。
- 原生 Pindo 收起面板，唤起／激活已安装的 Codex 桌面应用。用户在 Codex 中选择合适的项目与会话，再粘贴并发送；不自动按发送，也不把打开应用称作恢复了原任务。
- 复制失败时保留事项状态；唤起应用失败时说明“内容已复制，未能打开 Codex”，不显示任务已发送。未安装应用时可保留复制能力，不自动下载或安装。
- 如果不想复制，仅标记进行中也应能完成。

复制内容示例：

```text
任务：优化首页导航

说明：
先给出两个信息层级方案，确认方向后再继续。
保留现有登录入口。
```

不自动添加仓库路径、分支、执行命令或通用长提示词。交接目标是把用户已写好的想法带过去。

### 3. 从 Codex 回来，再挑一件

打开 Pindo 时，清楚看到已开始的事项，同时能继续挑选未开始的事项。无需反复翻日期、重新搜索或打开多层页面。

“进行中”不能因为计划日到了昨天就消失。建议在用户明确查看进行中时跨日期保留；日期仍用于挑选当天准备推进的待办，切日不自动移动历史事项。

不要切换回来就自动打开某条备注。用户这次可能要检查旧任务，也可能要开始新任务，先显示清单更容易选择。

### 4. 从进行中回到对应的 Codex 工作

核心问题是对应关系：多个任务并行后，要知道这条待办对应哪一个 Codex 任务。

先统一复制文本中的事项标题，便于在 Codex 中人工识别。第一轮“返回 Codex”表示回到桌面应用，不承诺自动选中那条事项对应的对话。

如果之后核实到用户版本提供稳定的会话链接，可以再允许为事项绑定链接；需要用两条并行任务验证链接分别打开正确对话。链接失效时保留原事项和应用切换能力，不改用猜测的路由。

## 桌面应用中的往返细节

- 全局“打开清单”快捷键呼出紧凑面板，不强制打开完整窗口；记录唤出前的前台应用，便于收起后回到原工作。
- 使用“复制并切到 Codex”时，先确保标题与备注复制成功，再收起 Pindo 面板并激活 Codex。剪贴板中保留完整文本，用户决定贴到哪个项目或对话。
- Codex 开始恢复或运行后，再按清单快捷键，从未开始事项中挑另一条；进行中区保留 A、B 等多条事项，便于之后找到并确认。
- “复制”“标为进行中”“切到应用”只描述 Pindo 完成的动作。Codex 是否接受、开始、结束，第一轮均不由 Pindo 自动判断。
- 保留现有“快速记录”快捷键。记录想法与挑选已有事项分别配置，避免每次等待时打开的都是新建输入框。

## 能力核查记录

核查来源为 OpenAI 官方仓库的固定提交 [`ddd1812`](https://github.com/openai/codex/tree/ddd1812a51f4aded35c3ec5446672474d5cb546b)。

- [桌面应用启动实现](https://github.com/openai/codex/blob/ddd1812a51f4aded35c3ec5446672474d5cb546b/codex-rs/cli/src/desktop_app/mac.rs)使用应用标识 `com.openai.codex`，并提供 `codex://threads/new?path=…` 新建工作线程入口。
- [CLI app 参数](https://github.com/openai/codex/blob/ddd1812a51f4aded35c3ec5446672474d5cb546b/codex-rs/cli/src/app_cmd.rs)接收工作目录路径。它不是已验证的“打开指定已有任务”接口，也不意味着 Pindo 必须管理项目目录。
- 第一轮原生实现只需通过 macOS 应用服务找到并激活已安装的 Codex，不调用可能下载／安装应用的 CLI 流程。
- 当前环境为 Linux，以上是官方源码核查，不是用户 Mac 上的版本或实际行为验证。没有穷尽所有客户端能力，也不据此断言桌面应用完全没有会话深链接。

## 备注仍然怎么用

点击事项主体继续打开附属备注；右侧铅笔继续修改事项；点击备注编辑区域外返回的现有规则保持。

备注可用于最少量的交接说明，例如“已经发给 Codex，回来先看页面切换是否顺手”。不要求用户复制整个对话，也不新增项目级便签。

“复制并切到 Codex”和状态操作的具体位置应在下一版界面中一起验证：不能挤掉右侧铅笔，也不能让普通单击事项变成启动 Codex。

## 第一轮的边界

- 不自动创建或启动 Codex 任务，不把复制等同于任务已发送。
- 不根据等待时间猜测 Codex 是否完成；完成仍由用户主动确认。
- 不要求配置开发环境、项目目录或终端。
- 不增加到点提醒、工时统计、复杂优先级或项目看板。
- 保留完整设置窗口、30 秒有变化才生成快照、最多 100 份／30 MB，以及设置内按需恢复。

## 验证这个设计是否顺手

用两条事项完整试一遍：记录 A、B → 复制并开始 A → 去 Codex → 回 Pindo 复制并开始 B → 去 Codex → 回 Pindo 找到 A → 回正确的 Codex 任务检查 → 勾选 A 完成。

重点看是否少复制漏备注、是否能清楚区分待开始和进行中、能否找到对应的 Codex 任务、进行中是否跨日可见，以及是否仍能轻松继续挑下一件。不能用只切换一个状态文字的静态演示代替完整流程验证。
