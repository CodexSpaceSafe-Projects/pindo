# 缤纷云加密同步

Pindo 的 macOS 与 Android 客户端使用用户自己的私有缤纷云存储桶和相同的恢复密钥。v2 把云端提交保存为不可变的加密完整检查点；本机编辑先落盘，联网后合并。

技术计划和故障矩阵见 [同步机制重设计](SYNC-REDESIGN.md)。当前提交的实际验证结果见 [验证记录](../VALIDATION.md) 和对应 GitHub Actions。

## 连接设备

1. 注册并实名认证[缤纷云](https://console.bitiful.com/)，创建私有存储桶。
2. 创建只可访问该桶的子用户 Access Key / Secret Key，授予列举、读取和写入对象权限。应用不会创建桶、公开桶或自动删除对象。
3. macOS 打开「设置 → 云同步」；Android 打开云同步设置。填写端点、桶名、区域和凭据。默认端点为 `https://s3.bitiful.net`，区域为 `cn-east-1`，其他值以控制台为准；仅接受缤纷云 HTTPS 端点。
4. 第一台设备使用**创建资料库**模式，生成恢复密钥并保存到密码管理器。其他设备使用**加入已有资料库**模式，填写相同的桶和恢复密钥；加入时不要生成另一把密钥。
5. 各端点击「立即同步」，检查新增事项、备注、状态和分组。确认后，再在另一端修改并验证回传。

加入模式必须找到可解密的有效资料；格式合法但不对应现有资料库的密钥不会被当作新空库自动创建。首次加入合并本机当前可见资料。同名事项或分组只要 ID 不同，仍是不同记录；分组重名时以 ID 后缀区分。

保存连接时，先进行只读验证，再提交本地资料库绑定与凭据事务。验证失败或被取消时不消耗尚未绑定的旧版同步历史；完整对象扫描和写入权限检查仍在正式同步时完成。

恢复密钥为随机 256 位密钥，以 64 位十六进制显示。macOS 凭据保存在 Keychain；Android 使用 Android Keystore 的 AES-GCM 密钥加密保存，并禁用系统云备份。云端、明文导出和快照不保存恢复密钥或 S3 凭据。密钥丢失且没有可用本地资料时，不能通过云账号找回明文。

## 断开、重连与切库

- **断开连接**停止本机网络同步并移除本机连接凭据，保留当前事项、因果历史、墓碑和待上传资料。重新连接同一资料库可继续这些修改。
- **连接不同资料库**时，已建立可识别绑定的原库会保留完整本地副本，包括可见资料、同步历史和发件箱。切回已保存的库时恢复该库自己的副本；新库的当前资料不会被隐式写回旧库。
- 本机最多保存 **8 个资料库副本，包含当前库**。旧库归档的序列化总量上限为 **64 MiB**；超过上限取消切换并保留原库，不自动丢弃旧库。
- 连接设置使用加密的 `active/pending` 事务日志，文档事务标记决定重启后完成哪次切换。凭据与文档绑定不一致、事务不能恢复或本地资料损坏时，停止网络并报告问题。
- 每次启动都在允许本地编辑前为后续操作分配新 actor，断开或离线启动也一样。旧操作身份不变，避免复制或回滚资料后复用旧操作编号。
- 在应用内恢复快照或导入资料，会保留本库同步历史，并把恢复结果记为新操作；导入文件的外部同步副本不被采用。快照不携带库绑定，恢复会写入当前资料库，操作前应确认当前连接。

断开不等于撤销云端凭据。需要撤销设备访问时，应在缤纷云控制台停用相应子用户密钥。更换恢复密钥得到另一个资料库标识，旧密文不会自动迁移、重新加密或删除。

升级前已经断开、且尚无可识别库绑定的 v1 副本，若明确选择创建新库，会以当前可见资料初始化，不把未知来源的同步历史带入新库。此前建议确认保存并退出应用，离线备份原始 `data.json`，另行保管旧恢复密钥。普通明文导出不含同步元数据，不能代替原始文件保留旧库的因果历史。

每个安装实例使用自己的本地资料目录。Android 使用 `singleTask` 入口，当前交互按单 Activity 任务设计。直接共享同一个 `data.json` 并发写入不属于该云协议的存储模型；不同设备通过云对象合并。

## 同步过程和状态

1. 将已提交编辑、副本和基线原子保存到本地。
2. 列举 v2 对象和兼容期的 v1 文件；对未缓存或 ETag 已变化的对象重新读取，逐个校验路径、版本、摘要、认证加密和 schema，再合并临时候选。
3. 本批成功后，把投影、副本和已处理对象缓存写入同一原子文件。单批下载预算为 **64 MiB**，开始下一对象前检查预算；末个对象最多额外占一个对象的空间。仍有未处理对象时继续下一批，保持待同步，不标记整轮成功。
4. 扫描完成后，将待上传路径、固定密文字节和对应明文摘要保存到持久发件箱，再上传。
5. PUT 后 GET 读回并核对相同密文，才确认该对象。请求超时但服务端可能已接收时，同样通过读回判断；重试使用相同 key 和 bytes。
6. 确认只适用于这份冻结提交。上传期间新增的修改仍待上传；自己的已确认对象消失时，重新发布本地完整检查点。

“本地已保存”“等待同步”“编辑中暂缓”“同步失败”和“已同步”不同。“已同步”表示对应本地版本已获远端确认，不表示另一台离线设备已收到，也不能保证云服务此后永远保存该对象。

前台按需和定时检查。macOS 活跃窗口通常约 30 秒轮询，无可见窗口时约 60 秒；失败退避，手动同步可主动重试。Android 离开前台后不承诺即时同步，返回应用后继续。休眠、进程终止、网络策略和系统后台调度会影响完成时间。

编辑保护使用可嵌套会话租约。备注组词、事项编辑、管理页交互会话或拖动尚未结束时，远端合并暂缓；关闭一层不会解除仍工作的另一层。关闭 macOS 设置窗口会提交已确认输入并释放所属会话；重新打开回到通用设置。最小化不会丢弃仍保留的编辑会话，恢复窗口或结束会话后继续同步。多窗口和输入法交互仍需实机验收。

## 合并规则

- 同步事项、三级父子关系、排序、状态、计划日、备注和分组。外观、字体、快捷键、登录启动、草稿、连接配置和本地快照属于本机。
- 普通字段以 Lamport 时钟及 actor ID 确定顺序。不同字段分别合并；同字段并发修改选定确定性获胜值，不依赖系统时钟一致。
- 备注使用因果多值寄存器。并发版本保留，用 `[Sync conflict]` 分隔显示；看到合并后的版本再编辑，可形成解决版本。相同文本显示去重，底层因果信息保留。
- v2 将 `phase`、`startedAt`、`completedAt`、`isProgressExplicit` 放入一个 `lifecycle` 寄存器，统一选择状态轮次，避免“未完成但带旧完成时间”等拼接。
- 删除记录保留墓碑。普通离线编辑不会复活已删 ID；明确恢复或重新创建会产生新的存在性操作。父项删除包含下级；并发新增或移动遇到失去父项时，按层级规则保留内容。
- 环、失去父项、超过三级的关系在投影中确定性地提升为主事项；失去分组的事项显示未分组。父项状态按子项进度和显式开始来源自底向上推导。

## 从 v1 升级

建议先在所有设备保留当前资料的明文导出或本地备份，再升级各端。

1. 新端只读验证并合并 `pindo/v1/<vaultID>/heads/` 的旧设备文件。
2. 先上传并 GET 确认 v2 初始检查点，再在旧目录写入升级标记。
3. 标记也是有效 v2 完整检查点，新端校验并参与合并。旧端遇到 version 2 会明确停止旧协议同步，提示升级；本机离线内容保留。
4. 新端继续只读吸收升级前已经发出、稍后到达的 v1 上传，不把 v2 业务变化写回 v1 设备头。

升级标记固定为：

```text
pindo/v1/<vaultID>/heads/ffffffff-ffff-ffff-ffff-ffffffffffff.json
```

若保留路径实际属于旧 writer、无法解密或内容损坏，停止迁移，不覆盖它。并发迁移可分别发布不可变初始提交；标记不作为全部资料的唯一权威副本。标记丢失时，在确认有效 v2 检查点后修复。

v1 生命周期原寄存器在升级时原样保留；新增 `lifecycle` 初始为空底值，不把不同旧字段版本拼成伪造新事件。真实 v2 生命周期优先，只有旧 `phase` 的版本严格更新时才采用旧状态来源并归一。单独晚到的旧时间字段不会推翻已选中的 v2 状态轮次。

直接降级程序可能无法读取新版本地同步状态。需要降级时应先保留可读明文资料；不要删除同步状态或覆盖云端目录来绕过版本检查。

## v2 格式

```text
pindo/v2/<vaultID>/objects/<SHA256(encryptedEnvelopeBytes)>.json
```

每个对象包含该次提交的完整合并状态。新修改使用新对象，旧请求晚到或响应丢失不会覆写较新对象。正确性不依赖服务端的条件 PUT、多版本或 WORM。

- 密钥为随机 32 字节；`vaultID = SHA256(key).hexLowercase.prefix(32)`。
- AES-256-GCM 使用随机 12 字节 nonce、16 字节 tag；v2 AAD 为 UTF-8 `PindoSync/v2/<vaultID>`。v1 保留 `PindoSync/v1/<vaultID>`，两者不能混用。
- 外层 JSON 是 `version`、`nonce`、`ciphertext`、`tag`，二进制字段使用标准 Base64；v2 envelope 的 `version` 为 `2`。
- 明文 `SyncPayload.version` 为 `2`，保留 `seen` 和 `records`。记录键为 `task:<lowercaseUUID>` 或 `group:<lowercaseUUID>`；寄存器为 `{value,stamp:{counter,deviceID}}`，`$alive` 为存在性寄存器。
- 事项保留 v1 raw 字段及 `notes`，新增 `lifecycle` 寄存器。非空值包含 `phase`、`startedAt`、`completedAt`、`isProgressExplicit`；新生命周期用同一版本镜像旧字段，保留来源与版本比较能力。
- 时间仍为 **2001-01-01 UTC 起的秒数**，转换 Unix 秒加 `978307200`；计划日为 `{year,month,day}`。同步 ID 和摘要使用小写。
- 发件箱、确认缓存、旧头 ETag、库归档和事务标记只在本地保存，不进入同步明文、导出或快照。

## 容量、损坏和恢复边界

| 项目 | 上限或行为 |
| --- | --- |
| 单个同步明文 / 加密对象 | 7 MiB / 10 MiB |
| v2 不可变对象 | 每库最多 10,000 个 |
| 兼容期 v1 文件 | 最多 100 个业务头，另加 1 个升级标记 |
| 单批下载 | 64 MiB 预算，按完整对象分批 |
| 本机资料库 | 包含当前库最多 8 个，旧库归档合计最多 64 MiB |
| 历史与墓碑 | 当前不自动删除 |

完整检查点会增加对象数量和存储占用。达到上限、无法生成合规检查点、格式错误、未知版本或解密失败时，保留本地未确认资料和云端已有对象，停止相应步骤并报告原因；不把部分扫描当作已同步，不按年龄清除墓碑。人工整理云端对象前，应保留可恢复备份并确认各端状态。

认证加密和路径摘要能够检测被读取对象的篡改、损坏或错库复制。已缓存 key 的 ETag 变化会触发重新校验；本版不执行全量周期完整性审计，服务端错误或恶意保持相同 ETag 的改写只能在对象再次被读取时发现。应用不能阻止拥有存储权限的人删除文件。所有本地副本与云端历史同时丢失，或恢复密钥与全部可读本地资料同时丢失时，无法凭空重建内容。

## 请求费用和验证边界

本版采用轮询，没有存储实时推送。每轮列举旧目录和 v2 目录；未缓存对象、上传读回和升级检查产生额外请求。首次加入或恢复缓存时流量更高。请求额度由整个云账号共享。

免费额度、按日上限和收费应以[缤纷云当前计费规则](https://docs.bitiful.com/prices/basic)及控制台为准；CDN 额度不能当作直连同步额度。根据设备数量、轮询时间和检查点大小评估实际费用。

自动验证包括跨语言向量、三端性质测试、模拟网络/存储故障及 macOS、Android 构建检查。实际通过状态见当前提交的 CI 和 [验证记录](../VALIDATION.md)。

未配置真实云桶时，这些验证不能证明真实连通性、跨区域一致性、运营商延迟或 OS 后台行为。正式使用前，按[故障矩阵](SYNC-REDESIGN.md#故障与验收矩阵)完成真实两端/三端演练和备份恢复验收。
