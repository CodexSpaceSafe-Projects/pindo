# 多端同步 v2：执行计划与验收矩阵

本次重设计继续使用用户自己的缤纷云私有桶、S3 请求签名和端到端加密。目标是让每个被考虑的故障都有确定的恢复路径和验收条件。本文记录先制定再实施的工程计划；通过数量、提交和构建结果由 [VALIDATION.md](../VALIDATION.md) 记录。

## 执行计划

1. 审查 Swift/Kotlin 协议、网络、仓库和界面生命周期，整理会导致数据丢失、误确认或跨库写入的反例。
2. 定义跨端一致的不变量、v2 wire 格式、迁移顺序、容量与失败策略。
3. 实现内容寻址的不可变完整检查点、固定字节的持久发件箱和上传后的 GET 确认。
4. 实现生命周期原子寄存器、v1 来源保留、每启动新 actor、跨端协议向量和收敛测试。
5. 实现资料库绑定、按库归档、连接事务恢复、可嵌套编辑保护和有资源预算的同步状态机。
6. 实现先确认 v2 再设置旧协议屏障的升级流程，测试旧端迟到上传、并发迁移和标记恢复。
7. 运行核心测试、macOS 原生测试/打包、Android 测试/lint/构建，核对同一提交；将真实云桶和实机仍待确认的项目单独列出。

## 必须保持的不变量

- 事项、合并副本、投影基线、已处理对象缓存和相应确认状态在同一原子文档中提交。
- 下载成功不等于已应用。写盘失败或编辑会话阻止应用时，不能提前记录已处理对象。
- 新提交先落入持久发件箱，再发起网络写入。发件箱固定对象 key、密文字节和对应明文摘要。
- 网络确认只确认实际发出的那份冻结对象；上传期间产生的新修改仍是待上传状态。
- PUT 超时后，读回相同对象可确认已提交；仅发出请求或本地内容未变不构成成功。
- v2 权威资料由有效不可变对象的合并得到；新修改使用新 key，晚到旧 PUT 无法把新对象改回旧内容。
- 已知 key 的 LIST ETag 改变时重新读取并校验，不能仅因 key 已缓存就永久忽略可观察的对象改写。
- 故障模型内的合并满足交换性、结合性和幂等性；重复、乱序传递不改变最终结果。
- v1 原字段原样升级；新增生命周期空底值不能覆盖真实事件，也不拼接不同旧字段版本产生伪造事件。
- 生命周期按 `phase` 事件与真实 v2 原子事件仲裁；单独晚到的旧时间字段不代表新状态轮次。
- 墓碑属于同步历史。普通离线编辑不恢复已删 ID；显式恢复通过新的存在性操作表达。
- 新 actor 在允许本地编辑前建立，离线或断开启动也一样；旧操作身份不被重写。
- 同库重连保留历史，切回旧库恢复该库自己的可见资料、副本和发件箱。
- 加入模式不能把错误密钥对应的空命名空间自动当作新库。
- 新连接先只读验证，再提交本地绑定，验证失败或取消不消耗尚未绑定的 v1 历史。
- 连接切换由加密 `active/pending` 日志和文档事务标记共同恢复；绑定不明或不一致时停止网络。
- 导出、快照和云端业务载荷不携带连接秘密、库归档、发件箱或事务标记。

## 协议与工作循环

完整格式和配置步骤见 [SYNC.md](SYNC.md)。云端路径为：

```text
v2 对象：pindo/v2/<vaultID>/objects/<SHA256(envelopeBytes)>.json
旧版输入：pindo/v1/<vaultID>/heads/<deviceID>.json
升级标记：pindo/v1/<vaultID>/heads/ffffffff-ffff-ffff-ffff-ffffffffffff.json
```

```text
本地已保存
  → 列举、逐对象验证并合并候选
  → 原子应用本批及其缓存
  → 尚有未读对象：保持待同步并继续下一批
  → 扫描完成：持久化冻结发件箱
  → PUT、GET 验证
  → 只确认这份提交
  → 确认或修复升级标记
  → 仍有本地修改：继续；否则记录本轮成功
```

应用候选和确认前重新检查编辑租约、连接 generation 和恢复状态。取消不能证明服务端未收到请求；不可变对象使晚到请求不会覆写新状态。网络错误保留发件箱并进入退避，用户可手动重试。

单批以 64 MiB 下载预算为边界，按完整对象校验，不同时缓存全部远端检查点。末个对象最多额外占一个对象的空间。已验证并提交的前批可以保留；未完成扫描时保持待同步，不发布升级成功或整轮成功。损坏对象不被静默跳过，本批不推进对应缓存。

## v1 迁移顺序

1. 验证旧输入和已有 v2 对象，合并到持久本地副本。
2. 把初始 v2 完整检查点存入发件箱并上传，GET 验证字节。
3. 检查升级保留路径未被真实 v1 writer 占用，再写入一个有效 v2 检查点作为标记并验证。
4. 旧客户端读到 envelope version 2 后明确停止旧协议同步。新端继续只读吸收已在途的 v1 写入。
5. 标记参与合并，但不取代全部不可变对象。标记丢失可在确认检查点后重建；未知或损坏的占用不能直接覆盖。

此流程不依赖未经真实验证的缤纷云条件写。兼容范围是读取 v1、迁移和让旧端停止旧协议；不会把 v2 业务状态双写回旧设备 head。直接降级程序需要单独保留可读资料。

## 故障与验收矩阵

“自动测试要求”列给出验收断言和测试责任，不表示每种现实环境已经通过。实际执行状态应核对当前提交的核心、macOS 和 Android 测试记录。

| 场景 | 机制与必须成立的结果 | 自动测试要求 | 仍需实测 |
| --- | --- | --- | --- |
| 空本地加入有资料云库 | 有效密文合并；空集合不是全量删除 | 空端加入保留远端任务、分组、墓碑 | 新安装 Mac/Android 加入真实桶 |
| 多端同时首次创建 | 各自发布不可变对象，最终合并全部 ID | 三端排列、重复投递、收敛 | 同桶多设备同时连接 |
| 合法格式但错误的密钥 | 加入模式无有效对象即报错 | 错 key 后改回原 key，墓碑和离线编辑保留 | 错误桶、区域和密钥提示 |
| 同字段/不同字段并发 | 确定性 LWW；独立字段分别保留 | 交换律、结合律、幂等性 | 三端离线编辑后恢复网络 |
| 并发备注 | 保留因果多版本，显示去重 | 中文、emoji、重复文本、解决后重放 | 输入法、长备注和冲突处理 |
| 完成/开始/重开并发 | 生命周期作为一致事件选择 | pending 不带旧 completedAt，轮次一致 | 状态按钮与元数据展示 |
| v1 时间字段晚到 | 保留 raw 来源，按 phase 事件仲裁 | 升级前后合并同结果，旧时间不复活旧 phase | 旧端在途操作后升级 |
| 显式父进行中与子项操作 | 显式来源参与同步和推导 | A 开始父项，B 开始/重开子项，全端一致 | 真实三级树操作 |
| 删除对离线编辑 | 墓碑保留，普通编辑不重建 `$alive` | 旧副本重放不复活任务或分组 | 长期离线设备重返 |
| 删除父项对并发新增子项 | 分支删除和确定性失父投影 | 内容保留、无环、最多三级 | 主清单和管理页树展示 |
| 并发移动、失去分组 | 保留原始寄存器，修复投影 | 到达顺序不影响树和排序 | 拖动、折叠、筛选 |
| 显式恢复和导入 | 保留本库历史，记录新操作 | 删除后可恢复，外部 replica 被忽略 | 保护备份与重启恢复 |
| 断开后离线编辑再重连 | 同库副本和发件箱保留 | 多次修改/删除不被旧云覆盖 | 飞行模式、断网、重新连接 |
| 重装、克隆、回滚资料 | 编辑前新 actor，旧事件不变 | 相同副本在独立本地存储中离线修改不产生重复 dot | 系统备份与文件迁移 |
| 已绑定 A → B → A 切库 | 按库归档完整资料和历史 | 恢复 A，不把 B 隐式写入 A | 两个真实库与 UI 说明 |
| 凭据/文档间崩溃 | 日志和文档事务标记共同决策 | 每个写入点失败后恢复唯一活动绑定 | Keychain/Keystore 锁定 |
| 凭据与回滚文档绑定不一致 | 阻止网络并保留资料 | B 凭据配 A 文档不得自动上传 A 到 B | 手工替换 data.json 后启动 |
| 下载时编辑、嵌套租约 | 延迟应用，逐层释放 | 候选不提前记缓存，管理页租约有效 | IME 候选字与多窗口 |
| 关闭或最小化编辑窗口 | 关闭提交已确认输入并释放所属会话，最小化保留会话 | 关闭设置后可继续同步，重开回通用 | IME 提交、sheet 关闭与窗口恢复 |
| 上传中继续修改 | 冻结发件箱，确认指定版本 | 旧 ACK 不清新修改，后续提交可上传 | 连续输入与退出 |
| LIST/GET 竞态、重复分页 | 路径、ETag、分页校验 | 版本变化、重复 key/token 不误确认 | 云端一致性与响应头 |
| PUT 落盘但响应丢失 | GET 核对固定字节 | 重试同 key/bytes，确认幂等 | 丢包、代理超时、弱网 |
| 旧 PUT 晚于新 PUT | 不同提交 key，保留新对象 | 延迟旧上传后状态不回退 | 断网、杀进程、重启 |
| 在途断开或切库 | generation 和绑定重检 | 旧回调不能改新库或清新发件箱 | 前后台和 HTTP 取消 |
| 已确认对象消失 | 重新发布本地完整检查点 | 没有新编辑也补发 | 人工删除自身对象 |
| 篡改、未知版本、坏 JSON | 摘要、AEAD、schema 失败关闭 | 本批不推进缓存，不清空本地 | 故障对象诊断流程 |
| 已缓存 key 存在但 ETag 改变 | 重新下载并核对内容寻址摘要和认证加密 | 改写已有对象不能被 key 缓存跳过，错误时保留原缓存/副本 | 真实对象覆写与存储返回头 |
| 并发迁移、marker 丢失 | 先确认 v2 再写/修复标记 | 两迁移者、迟到旧头、marker-only 恢复 | 新旧客户端混用演练 |
| 保留 UUID 被 v1 writer 占用 | 停止迁移，不覆盖原头 | 真实占用得到可解释错误 | 特制旧资料恢复 |
| 100 个旧头加 marker | 标记不占业务设备配额 | 100 + marker 可读，101 个业务头拒绝 | 真实分页 |
| 超过单批下载预算 | 分批原子推进，未完成保持 pending | 跨批、批内失败、重启继续 | 低内存手机与大库加入 |
| 对象、明文或归档超限 | 保留资料，停止对应上传/切库 | 10,000 对象、7/10 MiB、8 库/64 MiB | 存储增长与费用 |
| 数值、日期和计数器边界 | 两端按同一范围验证，禁止截断或溢出 | 安全整数、非法日期、最大计数器、新操作耗尽 | 导入旧资料和跨时区展示 |
| 磁盘满或写盘失败 | 原子替换及事务恢复 | 提交点失败不推进确认/缓存 | 权限、磁盘满、系统崩溃 |
| 后台暂停、休眠、恢复网络 | 本地工作和发件箱保留 | 调度、取消、退避、手动重试 | OS 及厂商省电策略 |
| 全部副本或恢复能力丢失 | 明确不可恢复边界 | 错误状态不覆盖可读资料 | 独立备份与密钥保管 |

## 容量与后续压缩

本版保留不可变历史和墓碑，不自动 DELETE，也不假设缤纷云提供条件写、多版本、生命周期或对象锁。每库最多 10,000 个 v2 对象，单个明文/密文分别为 7 MiB/10 MiB。本机包含当前库最多 8 个库，旧库归档序列化合计最多 64 MiB。

存储模型要求各安装实例独立保存本地文档。Android 以 `singleTask` 入口约束当前单 Activity 任务。直接让多个进程共享并改写同一份 `data.json` 仍需要应用实例或文件写入互斥，不能由不可变云对象替代；克隆测试使用各自独立的本地目录。

按库归档依赖已识别的绑定。无绑定的旧 v1 副本显式创建新库时，只以可见资料初始化；创建前建议离线备份原始 `data.json` 并另存旧密钥。明文导出会排除同步元数据，不是保留旧因果历史的原始副本备份。

达到上限是明确的同步或切换失败状态，本地和云端已有资料保留。按天过期墓碑或删除任意旧设备文件可能导致长期离线设备复活数据，不能用来绕过上限。

未来自动压缩需要独立协议：先确认可恢复检查点，证明被删对象被保留状态支配，处理并发压缩、离线成员及删除权限失败。没有这些机制时，自动回收不属于本版保证范围。
